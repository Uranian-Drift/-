# 电商GTM AI经营分析系统 5.0

这是从当前4.9独立复制的5.0本地版本，4.9不会被覆盖。5.0重点统一经营总览的时间口径：页面只选择分析截止日，固定拆分为当月经营判断、年累与当月对照、当月经营拆解、滚动趋势与最新监控四层。

## 5.0 时间口径总览

- 年累固定为当年1月1日至分析截止日，只用于全年进度与形态盘面对照。
- 当月固定为截止日所在月1日至截止日，用于经营结论、店铺、重点系列和型号TOP10。
- 16N1日销与渠道趋势固定为截止日前30天，并单独标记日期范围。
- 收入使用最新完整审核月，价格使用最新监控日期，均不与年累或当月混算。
- 经营总览隐藏开始日期和快捷周期，只保留分析截止日；其他专业页面仍保留原起止日期筛选。

## 4.9 精简决策总览

- 首屏先给出价格动作建议，并把当月销额、台量、均价和结构补位合并为四张决策卡。
- 年累与月累进度保留目标完成率、计划节奏差额和剩余日均要求。
- 全年目标读取“分货盘总览”的26年全年预计；目标口径展开后展示7—12月销售目标及较上年同月增幅。
- 均价与销售指数不展示数值型目标，经营判断统一以“高于同期”为标准。
- 蝶翼、平衡机和其他产品改为一行增长补位等式，快速判断增长盘能否覆盖收缩盘。
- 店铺经营只保留销售前6店铺和其他，以及有效销售、三类形态和经营状态。
- 16N1只保留四个作战指标，店铺贡献明细默认收起。
- 18M2、16M1和竞品价格改成摘要卡，完整店铺表、价格曲线和竞品明细按需展开。
- 18M2、16M1系列摘要和店铺明细同时展示销售额与有效台量；16M1同期按升级关系合并02-MS16T1与MS16T2。
- 目标及计划节奏口径默认收起，降低会议首屏的信息密度。

## 4.8 经营决策总览

- 自动给出当月计划差额、剩余目标、所需日销倍数和价格动作建议。
- 年累与月累进度同时显示实际完成率、截至当天计划应达、计划差额与剩余日均要求。
- 价量决策同时比较销额完成、台量完成、当前均价、目标均价与均价差。
- 形态增长补位展示蝶翼、平衡机的增长能否覆盖其他产品下滑，并显示各形态目标缺口。
- 渠道经营责任表不虚构渠道目标，按销售、同比、三类形态表现与增长覆盖率判断经营健康度。

## 4.7 经营总览

- 整体、蝶翼、平衡机、其他的有效销售、同比和目标完成率。
- 目标读取“目标”文件夹中的2026H2模拟器，并按月、型号和新版形态汇总。
- 六类重点渠道/店铺有效销售、同期、同比及分形态销售。
- 16N1五类重点渠道分日销售曲线，以及18M2、16M1系列分渠道表现。
- 其他专业模块和4.6的均价影响拆解保持不变。

## 4.6 均价影响拆解

- 将整体成交均价变化拆成“自身价格影响”和“销售结构影响”，两项之和与整体均价增减一致。
- 可按型号、系列、形态、渠道和店铺切换分析维度。
- 同时展示正向贡献 Top 5、负向贡献 Top 5 和完整明细，明细可隐藏。
- 明确标记持续、新增和退出项目；新增、退出项目的贡献计入销售结构影响。
- 型号、渠道和店铺名称支持点击跳转至对应经营效率页面。

## 4.5 AI升级

- 三种分析模式：快速查询、专业分析、深度诊断；默认使用深度诊断。
- DeepSeek先理解问题并规划多项分析任务，再由浏览器本地执行安全的聚合查询。
- 语义层统一销售、奥维和产品索引口径，可跨型号、系列、形态、渠道、店铺、价格段等维度分析。
- 深度模式最多执行 15 项查询，保留更完整的Top结果、趋势和交叉证据。
- 经营答案包含结论、核心发现、驱动因素、风险、行动清单、验证指标和后续追问。
- 专业与深度模式启用第二次 DeepSeek 复核，检查数字、逻辑、因果措辞和行动可执行性。
- 支持在页面维护当前目标、优先事项、近期活动、业务约束和补充说明。
- 增强会话记忆，后续提问可继承上一轮的结论、驱动因素和行动建议。
- 原始订单明细不会发送给模型，只发送浏览器本地计算后的聚合证据。

## 分析流程

1. 结合问题、当前筛选、经营背景和历史对话制定查询计划。
2. 浏览器本地执行销售、奥维或跨数据源查询。
3. 将聚合后的证据包交给 DeepSeek 生成经营判断和行动方案。
4. 独立复核答案中的数字、逻辑、风险与建议，必要时返回修订结果。

当前数据没有可靠成本字段，因此系统不推算毛利或毛利率。

## 本地预览

需要通过本地静态服务打开，不要直接双击 `index.html` 使用 `file://`。本地没有 Netlify Functions 时，系统会自动给出基于真实聚合证据的本地分析摘要；部署并配置函数后才调用 DeepSeek。

## 共用基础数据

原始销售、奥维、型号、目标和价格监控数据统一位于 `../../00-基础数据/`。更新数据后，运行 `scripts/build_dashboard_data.py` 重新生成本看板的 `data/water-heater-data.js`。

## Netlify配置

如果后续部署，需将当前版本目录发布，并在 Netlify 环境变量中配置 `DEEPSEEK_API_KEY`。`netlify/functions/deepseek.js` 会在服务端读取密钥，网页端不会保存密钥。

## 关键目录

- `ai/`：深度规划、经营分析、独立复核、对话控制与记忆
- `engine/`：语义层、多查询引擎、证据包和原有指标能力
- `config/`：AI模式、安全白名单和经营背景
- `netlify/functions/`：DeepSeek服务端代理
- `qa/`：本地验收脚本
